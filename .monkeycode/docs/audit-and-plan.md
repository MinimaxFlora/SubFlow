### 1.3 Sub-Store 研究结论（详见 `docs/research/sub-store-storage.md`）

- 未使用任何关系型数据库；`database.js` 只是数组帮助函数。
- 持久化 = 进程内 JSON 对象 + 全量覆盖写文件（Node 下为 `sub-store.json` 与 `root.json`）。
- 无事务、无锁、无原子写入；并发与异常退出存在数据损坏风险。
- 已据此确定 SubFlow 采用 **SQLite（`modernc.org/sqlite`，纯 Go）** 作为默认持久化方案。

## 3. 实施计划

采用分阶段推进，每阶段以“可运行 + 可验证”为完成标准。

### 阶段 0：现状审计与研究（本阶段）

- [x] 审计仓库与工具链。
- [x] 完成 Sub-Store 存储机制研究并输出 `docs/research/sub-store-storage.md`。
- [x] 确定 SQLite 选型。
- [x] 输出功能矩阵、实施计划、风险与验收标准（本文档）。

### 阶段 1：项目骨架与基础设施

- Go Module 与目录结构（`backend/cmd`、`backend/internal/...`）。
- 配置层：命令行参数、环境变量、配置文件，明确优先级。
- SQLite 存储层：连接、PRAGMA（WAL、foreign_keys、busy_timeout）、版本化迁移。
- HTTP 服务：路由、统一响应与错误结构、健康检查、优雅关闭。
- 前端骨架：Vue 3 + TS + Vite + Naive UI，接入健康检查与一个真实列表页。
- 构建体系：`Makefile`、前端资源嵌入二进制、`Dockerfile`、`compose.yaml`、`.dockerignore`。

### 阶段 2：核心领域

- 统一节点模型与协议解析（VLESS、VMess、Trojan、Shadowsocks、Hysteria2、TUIC）。
- 处理链（可组合处理器 + 单元测试）。
- 格式适配器（URI/Base64、Clash、sing-box），每格式配真实样例测试。
- 订阅与集合的持久化与 API 打通。

### 阶段 3：持久化增强与安全

- 备份/恢复/导入导出，归档回收站。
- SSRF 防护（协议白名单、重定向与私网地址限制）、超时与并发限制。
- 敏感字段（订阅 URL、token）脱敏，日志不记录凭据。

### 阶段 4：sing-box 版本兼容

- 追踪最新稳定版与预发布版。
- 用真实 `sing-box` 可执行文件做配置校验，建立回归样例。

### 阶段 5：双部署与质量门禁

- 二进制干净环境启动验证。
- Docker 构建、启动、持久化、升级验证（本环境无 Docker，需在具备 Docker 的环境执行）。
- `make check` 全量质量检查。

## 4. 风险清单

| 风险 | 影响 | 应对 |
| --- | --- | --- |
| 本环境无 Docker | 无法本地验证镜像构建 | Dockerfile/Compose 做静态与 lint 校验；在具备 Docker 的环境执行 `make docker-test` |
| 协议与格式细节多 | 兼容性易出错 | 每种格式配真实样例与解析/转换测试，不凭格式名宣称兼容 |
| sing-box 迭代快 | 配置字段变更导致失效 | 建立版本矩阵与回归样例，用真实二进制校验 |
| 单一 SQLite 文件 | 并发写与损坏风险 | 启用 WAL、busy_timeout，写事务化，原子备份 |
| 脚本执行 | 任意代码执行风险 | 定义权限边界、超时、资源限制与错误隔离 |
| 订阅抓取 | SSRF / 内网探测 | 协议白名单、重定向与私网地址校验、超时限制 |
| 依赖供应链 | 引入不可信依赖 | 只用成熟且维护活跃的依赖，锁定版本 |

## 5. 验收标准

项目级验收（对应 SubFlow 规范第 15 节）：

1. Sub-Store 存储研究有源码证据，数据库选型有理由且有可执行实现。
2. 二进制部署可在干净环境启动、访问前端、初始化数据库并重启后保留数据。
3. Docker 部署可构建、启动、持久化、升级。
4. `Makefile` 的构建与检查目标真实可用。
5. 订阅管理与转换主流程端到端可用。
6. 最新稳定版与预发布版 sing-box 均有明确测试结论。
7. 备份、恢复、迁移与安全边界经过验证。
8. 不存在占位实现、虚假状态或跳过检查制造的“完成”。

单一功能验收：有真实业务行为、UI 与 API 一致、数据可持久化、错误场景有处理、有自动化测试、文档已更新、不破坏既有功能、构建与检查通过。
